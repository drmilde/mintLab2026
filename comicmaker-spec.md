# GOAL
I need a gradio app, that allows me to generate a single page of a comic book with 4 to 6 panels. I want to use this app as an easy to use interface for a STEM course for girls at the age of 12. The course is in German. 


# USER INTERFACE & TAB SPECIFICATIONS

The interface guides the user step-by-step through a structured linear workflow using 6 sequentially ordered tabs.

The user interface is structured into 6 Tabs: Creator, Characters, Scene, Script, Page, Export. The tabs should guide the user through the process of the comic page generation. First the user chooses his or her artist name and acronym. Then the characters of the page are described in more detail. Next the scene of page is described as well as the story of the page. This is done by describing the start of the story and the end of the story. Based on this information the story of the page will be generated by an LLM as a description of all the panels on the page. Finally this story is taken and a prompt for the image generation of the final page is created and processed by an image generation server. This image is then displayed to the user. In the final step the image can be exported and uploaded to a print server. 

## TAB 1: "CREATOR" (Künstler/in)

* **Purpose:** Onboards the user and sets artist metadata to personalize the final export.

* **UI Elements:**
* **Artist Name (`Künstlername`):** Text input field for the creator's full or alias name.
* **Artist Acronym/Signature (`Kürzel`):** Short text input (2–4 letters) used for stamping panel corners or signatures.
* **Comic Title (`Comic-Titel`):** Optional text input for the overarching title of the comic page.
* **Generate Button(`Signature`)**: use the krea2 image generation server to create a grafitti style signature logo from the artits acronym/siganture. 
* **Signatire Image Display:** Image component showing the generated signature logo.
* **Welcome & Instructions Banner:** Brief, encouraging German text explaining the workflow (e.g., *"Willkommen! Erstelle deine eigene Comic-Seite in 6 einfachen Schritten."*).

## TAB 2: "CHARACTERS" (Figuren)

The interface should allow the children to describe up to three characters that are shown on the page. 

* **Purpose:** Defines the visual appearance and personalities of up to 3 main characters to ensure visual consistency across panels.
* **UI Elements:**
* **Character Accordions / Forms (1 to 3 Characters):**
* **Name (`Name der Figur`):** Text input (e.g., "Lina", "Robot-X").
* **Visual Appearance (`Aussehen & Kleidung`):** Text area specifying hair color, clothing, distinct STEM gear (e.g., lab coat, safety goggles, magnifying glass).
* **Personality / Role (`Eigenschaften`):** Short text field describing their role or vibe (e.g., "neugierige Forscherin", "hilfsbereiter Roboter").
* **Preset Example Buttons:** A quick-fill button ("Beispiel laden") to populate fields with sample STEM-themed characters for fast testing.

## TAB 3: "SCENE" (Szene & Story)

There should be an input field, that allows to describe the overall setting of the scene. I also want to specify the description of the start scene and the final target or goal of the scene. Reference to the characters of tab 2 are given by using their names. Please also add a slider for selecting the number of panels (between 4 and 6).

Based on information given in the tabs 1 to 3, a script like description of the panels (between 4 and 6) should be generated using a call to a running ollama server with a gemma4 model running. For each panel there must be a description of the image of the panel, the text of the text box describing the panel as part of the story, and a possible dialog between the characters in the panel. 
This final script should then be displayed in a larger textarea, to be inspected and possibly edited by the user. 

Please note, that the text for the text bubbles of the characters, as well as the descriptive text parts for the panel should be brief and in a simple, easy to understand language. The texts must fit into the descriptive text boxes and the text bubbles. All texts are in German.

* **Purpose:** Sets the environment, story arc, and panel count, then triggers the generation of the initial script draft via Ollama.
* **UI Elements:**
* **Overall Setting (`Umgebung / Ort`):** Text area for setting descriptions (e.g., "Ein modernes Schul-Labor mit bunten Flüssigkeiten und Computern").
* **Story Start (`Anfang der Geschichte`):** Text area describing how the scene begins (e.g., "Lina entdeckt eine seltsame leuchtende Formel an der Tafel").
* **Story Goal / End (`Ziel / Ende der Geschichte`):** Text area describing the resolution (e.g., "Sie lösen gemeinsam das Rätsel und starten das Experiment erfolgreich").
* **Panel Count Slider (`Anzahl der Panels`):** Integer slider constrained between 4 and 6 (default: 4).
* **Action Button:** Prominent button titled **"Script generieren"** (Generate Script).
* **Backend Trigger:** Calls Ollama (Gemma 4 model) using system prompts from `.env`. The output is generated in German and automatically populates Tab 4.

## TAB 4: "SCRIPT" (Drehbuch & Panel-Details)

* **Purpose:** Displays the LLM-generated panel breakdown and allows manual inspection/editing before image creation.
* **UI Elements:**
* **Master Script Editor (`Gesamtes Skript`):** Large, editable text area containing the complete raw output from Ollama for quick review.
* **Structured Panel Cards (Dynamic 4–6 blocks):**
For each panel ($1 \dots N$), an editable layout with:
* **Visual Description (`Bildbeschreibung`):** Used later for image prompt synthesis (e.g., "Lina blickt überrascht auf das Mikroskop").
* **Narrative Text Box (`Erzähler-Text`):** Brief caption text at the top/bottom of the panel (max ~15 words).
* **Dialogue Bubbles (`Sprechblasen`):** Specific speaker-dialogue pairs (e.g., *Lina: "Das gibt's doch gar nicht!"*).


* **Constraints Note:** Visual reminder for users that text must remain concise and simple to fit inside final comic bubbles.
* **Action Button:** **"Weiter zu Page Generation"** (Passes verified script data to Tab 5).


## TAB 5: "PAGE" (Comic-Seite Generieren)

* **Purpose:** Converts the refined script into visual panel prompts, communicates with the image generation backend, and displays the final composed comic page.
* **UI Elements:**
* **Style**: Text area to enter a more refined description of the style to be used for the comic page. 
* **Prompt Synthesizer & Preview:** Displays the final combined visual prompt sent to the image generator (incorporating artist style, character details, and panel layouts).
* **Generate Button:** **"Comic-Seite zeichnen"** (Renders comic page).
* **Progress Indicator:** Loading bar / spinner showing generation progress.
* **Final Image Display:** High-resolution image component showing the generated 4–6 panel comic page.
* **Regenerate Option:** Secondary button to retry image generation if the result needs adjustments.

## TAB 6: "EXPORT" (Export & Druck)

* **Purpose:** Prepares the final comic page for download or sends it to an external print server.
* **UI Elements:**
* **Final Page Preview:** Read-only image view showing the finished comic with Creator signature metadata.
* **Local Download:** Button to download the high-resolution PNG/PDF file.
* **Print Server Integration (`Drucken / Absenden`):** Button to trigger an API POST request uploading the image and metadata (Artist Name, Title, Timestamp) to a print server/queue.
* **Status Feedback:** Success/Failure banner confirming print queue status in German (e.g., *"Super! Deine Comic-Seite wurde erfolgreich an den Drucker gesendet!"*).


# CODING

please python3.10 !

Please create the code in such a way, that the general behavior of the system as part of a hidden context, that is added to the prompt to ollama is configurable as an .env file. use the apprpoiate python libraries for this.

For the generation of the images you will connect to a comfyui server running a Krea2 image generation workflow. The api is specified in the file "krea2.json". Please use the code for talking with the server that you find in "comfy_krea2.py". The image return by the server should then be display in the gradio interface in tab 5 "Page".

The print server is implemented with a REST API. The POST endpoint is found unter "/api/v1/upload". Please make define variables in the .env file to configure the server adress, port and endpoint. 

1. **Environment Configuration (`.env`):**
* Use `python-dotenv` to manage hidden system prompts and server configurations.
* `.env` keys must include:
```env
OLLAMA_HOST=http://localhost:11434
OLLAMA_MODEL=gemma4:latest
IMAGE_GEN_API_URL=http://localhost:7860/sdapi/v1/txt2img
PRINT_SERVER_URL=http://print-server.local/api/upload
SYSTEM_PROMPT_GERMAN="Du bist ein kreativer Comic-Autor für Jugendliche..."

```

2. **LLM System Prompt Constraints:**
* The system prompt must instruct the Ollama model to write strictly in **German**, use simple language suitable for 12-year-olds, enforce character name consistency, and return cleanly parseable markdown per panel.


3. **Modular Code Structure:**
* Separate logic into `app.py` (Gradio UI), `llm_handler.py` (Ollama integration), `image_handler.py` (Image generation API calls), and `export_handler.py` (Print server integration).
